# 機能設計書

## 注文一覧取得

### 入力

`GET /orders`。

### 処理フロー

1. リクエストを受け付ける。
2. 注文を識別子順に取得する。
3. 利用者情報を取得する。
4. 注文と利用者をアプリケーション側で関連付ける。
5. 注文情報と利用者情報をレスポンス形式へ変換する。
6. 一覧をJSONとして返す。

### 出力

成功時はHTTP 200を返し、次の項目を持つ配列を返す。

| 項目          | 型      | 内容         |
| ------------- | ------- | ------------ |
| `orderId`     | integer | 注文識別子   |
| `userId`      | integer | 利用者識別子 |
| `userName`    | string  | 利用者名     |
| `status`      | string  | 注文状態     |
| `totalAmount` | integer | 合計金額     |

### エラー

- 注文が参照する利用者を取得できない場合は、内部データ不整合として明示的に扱う。

## データアクセス上の制約

シャーディング方針に基づき、OrdersとUsersは別シャードに配置される。シャードを跨ぐJOINは使用せず、各シャードから取得した情報をアプリケーション側で関連付ける。
