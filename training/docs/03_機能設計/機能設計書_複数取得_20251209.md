# 機能設計書（複数取得）

## API仕様

`GET /orders` は注文の `update_at` が新しい順に、クエリパラメータ `limit` で指定された件数の注文を返す。

`limit` は1以上100以下で、省略時は100とする。

同じ `update_at` の注文は注文IDの降順とする。レスポンスは次の項目を持つ配列である。

| 項目             | 型      | 内容                        |
| ---------------- | ------- | --------------------------- |
| `orderId`        | integer | 注文識別子                  |
| `customerName`   | string  | 顧客名                      |
| `deliveryStatus` | string  | 外部配送APIの最新ステータス |

## Service処理

1. Repositoryから `update_at` の降順、同値の場合は注文IDの降順で、`limit` 件の注文を取得する。
2. 注文ごとに、順番に1件ずつ外部配送APIの配送ステータスを取得する。
3. 注文情報と配送ステータスをレスポンスへ変換する。
4. 外部APIの失敗は成功レスポンスに変換しない。

## 外部APIクライアント

[外部API仕様書（配送ステータス）](../02_方式設計/外部API仕様書_配送ステータス_20251209.md)に従い、注文単位で配送ステータスを取得する。

タイムアウトを設定し、HTTPエラーを検出する。

## エラー処理

- `limit` が1未満または100超の場合はHTTP 422を返す。
- HTTP 429などの外部APIエラーやタイムアウトは検出し、成功レスポンスに変換しない。
