# 機能設計書

## API仕様

`GET /orders/{order_id}` は指定した注文を1件返す。注文が存在しない場合は404を返す。レスポンスは次の項目を持つオブジェクトである。

`GET /orders` は注文の `update_at` が新しい順に、クエリパラメータ `limit` で指定された件数の注文を返す。`limit` は1以上100以下で、省略時は100とする。範囲外の値を指定した場合は422を返す。同じ `update_at` の注文は注文IDの降順とする。レスポンスは次の項目を持つ配列である。

| 項目             | 型      | 内容                        |
| ---------------- | ------- | --------------------------- |
| `orderId`        | integer | 注文識別子                  |
| `customerName`   | string  | 顧客名                      |
| `deliveryStatus` | string  | 外部配送APIの最新ステータス |

## Service処理

1. Repositoryから `update_at` の降順で最大100件の注文を取得する。
2. 注文ごとに外部配送APIの配送ステータスを取得する。
3. 注文情報と配送ステータスをレスポンスへ変換する。
4. 外部APIの失敗は成功レスポンスに変換しない。

複数注文の処理では、外部APIの同時実行制限を超えないこと。

## 外部APIクライアント

- エンドポイントは `GET /delivery-status/{order_id}`。
- 正常時は `{ "order_id": 1001, "status": "delivered" }` を返す。
- タイムアウトを設定し、HTTPエラーを検出する。

## エラー処理

HTTP 429などの外部APIエラーを検出する。失敗を成功レスポンスに変換しない。
